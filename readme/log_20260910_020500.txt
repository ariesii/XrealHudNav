核心任務：在不影響 XREAL 眼鏡輸出的前提下，為手機端打造專屬直向 HUD 儀表板，徹底根絕文字與時速重疊問題
================================================================================

【一、 問題背景與分析 (Problem Background & Analysis)】
1. 使用者回報截圖與需求：
   - 使用者在手機主畫面的「HUD 即時鏡像預覽」及「全螢幕 HUD 模式」中發現：
     文字（如路名「等待導航開始...」）、時速數字（「6 km/h」）、距離（「--」）與電量文字擠在同一行，互相重疊打架，畫面極度雜亂無法閱讀。
   - 使用者明確要求：
     「在不影響眼鏡輸出畫面的情況之下，請幫我在手機上也可以完整的獲取這些訊息，因為目前看到的全螢幕的顯示事實上是會疊加跟不清楚的，我希望在不戴眼鏡的時候也可以清楚的獲得這些資訊。」

2. 根源技術原因分析：
   - 外接 XREAL Air 2 Pro 眼鏡螢幕規格為 1920x1080 (16:9) 超寬橫向空間，原本的 presentation_xreal_hud.xml 設計將「導航轉向/路名」置於最左側，而「GPS 車速/電量/測速照相」置於最右側，兩者橫向間隔超過 1000 像素，在眼鏡視場中非常自然完美。
   - 但手機螢幕通常是直向持握（Portrait，寬度僅約 360dp ~ 412dp），如果手機端也直接 include 原本的 1080p 橫向佈局，左右兩端的巨大字體（50sp 路名與 96sp 車速）在有限的直螢幕寬度下必然會在中央迎面相撞、發生嚴重的層次重疊。

3. 最佳架構解決方案：
   - 保持外接眼鏡 Presentation 顯示 100% 不變：外接眼鏡依然使用 presentation_xreal_hud.xml，維持最寬闊的雙眼 HUD 視界，不受任何改動影響。
   - 為手機端獨立設計專屬直向儀表佈局：view_phone_hud_dashboard.xml
     將資訊重新梳理為 5 個垂直層次：
     * 第 1 層：頂部狀態列（地圖訊號來源膠囊、省電模式、即時電量）。
     * 第 2 層：核心轉向與距離動作區（左側 96dp 轉向圖標 + 右側 38sp 大距離與動作說明，左右並列、絕不重疊）。
     * 第 3 層：道路名稱橫幅橫條（22sp 道路名清晰獨立呈現）。
     * 第 4 層：即時 GPS 車速與測速相機提醒列（左側 50sp 綠色大數字車速 + 右側測速照相膠囊）。
     * 第 5 層：動態車道線引導與紅綠燈倒數秒數膠囊（🔴 24s）。
   - 手機端主畫面預覽視窗 (previewWindow) 與全螢幕視窗 (layoutFullscreenHud) 全面接入此直向儀表，透過 PhoneHudViewHolder 統一雙向綁定。

【技術除錯與經驗學習重點 (Troubleshooting & Best Practice)】
- 遇到的編譯錯誤：
  Caused by: view_phone_hud_dashboard.xml:96:37: Error: The string "--" is not permitted within comments.
- 原因剖析：
  根據 XML 1.0 規範 (W3C Recommendation)，XML 註解結構為 <!-- ... -->，規範嚴格禁止在註解文字內部出現連續兩個減號「--」或以「--->」結尾。
  原本在 layout 註解中撰寫了「<!-- 超大距離數字 (如 48公尺 或 --) -->」，在 AAPT2 / DataBinding 解析 XML 時被 SAX 解析器攔截報錯。
- 解決方案：
  將該註解調整為「<!-- 超大距離數字 (如 48公尺 或 橫線) -->」，並使用 Python 腳本全面自動檢測 app/src/main/res/ 下所有 XML 檔案，確認全部通過。
